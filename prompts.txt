=== Prompt 2.1: layout, catalogue page, partials and the login page (web/templates, web/static) ===

You are a senior Go engineer working in the repository of "Albums API" (Go module `homework`, Go 1.25,
net/http ServeMux with method patterns, GORM + pgx on PostgreSQL 16; roles member / staff / admin; a
JSON REST API under /api/v1 that stays unchanged). Lesson 10 adds a server-rendered web UI with
html/template and htmx. Generate the templates and the stylesheet only; the Go handlers come from a
later prompt. Templates are parsed with html/template.ParseFS from an embedded filesystem whose root
is `web/templates`, so the file names below are the template names: "layout.html", "catalog.html",
"login.html", "partials/album_row.html", "partials/album_rows.html". Each page is its own template
set: the handler clones the parsed layout + partials and parses one page file into the clone, so a
page may override the blocks of the layout.

The data the handlers pass to the templates (field names are fixed, use exactly these):

  page data (every page):
    .Title       string                        page title
    .User        *struct{Email, Role string}   nil for an anonymous visitor
    .CanDelete   bool                          true for staff and admin
    .Query       string                        the current search text on the catalogue, "" elsewhere
    .Albums      []row                         catalogue rows (page and fragment)
    .Error       string                        login page: message after a failed login, "" otherwise
  row (one album):
    .ID          int64
    .Title       string
    .Artists     string                        artist names joined with ", "
    .Genre       string
    .ReleaseYear *int                          nil when unknown: render an empty cell
    .Label       string
    .Available   int                           copies with status available
    .Total       int                           all copies
    .CanDelete   bool                          the page flag copied onto every row

Produce these files and nothing else:

1. `web/templates/layout.html`: `<!doctype html>` (lower case), `<html lang="en">`, a `<head>` with
   `<meta charset="utf-8">`, a viewport meta, `<title>{{block "title" .}}Albums{{end}}</title>`,
   `<link rel="stylesheet" href="/static/app.css">` and `<script src="/static/htmx.min.js" defer></script>`.
   The `<body>` has a `<header class="topbar">` with the brand link `<a href="/catalog">Albums</a>` and
   a user box: when `.User` is set show `<span class="user">{{.User.Email}} ({{.User.Role}})</span>`
   and a logout form `<form method="post" action="/logout" class="inline">` with a submit button
   "Log out"; otherwise the link `<a href="/login">Log in</a>`. Then
   `<main class="container">{{block "content" .}}{{end}}</main>`. No inline JavaScript anywhere.

2. `web/templates/catalog.html`: `{{define "title"}}Catalogue - Albums{{end}}` and `{{define "content"}}`
   with `<h1>Catalogue</h1>`; a search form `<form method="get" action="/catalog" class="search"
   role="search">` containing exactly one input
   `<input type="search" name="q" value="{{.Query}}" placeholder="Search by album or artist"
   autocomplete="off" hx-get="/web/albums" hx-trigger="keyup changed delay:300ms"
   hx-target="#album-list" hx-swap="innerHTML">` and a submit button "Search" (the form works without
   JavaScript: a plain submit reloads /catalog?q=...); a `<table class="albums">` whose `<thead>` has
   the columns Title, Artists, Genre, Year, Label, Copies and, only `{{if .CanDelete}}`, an empty
   actions column; `<tbody id="album-list">{{template "album_rows" .}}</tbody>`. Under the table a
   `<p class="hint">` explaining that Copies shows available/total.

3. `web/templates/partials/album_rows.html`: `{{define "album_rows"}}` ranging over `.Albums` and
   rendering `{{template "album_row" .}}` for each; the `{{else}}` branch renders exactly one row
   `<tr class="empty"><td colspan="7">No albums match your search.</td></tr>`. The fragment must be
   table rows only: no wrapping element and no tag other than tr/td in this file.

4. `web/templates/partials/album_row.html`: `{{define "album_row"}}` rendering
   `<tr id="album-{{.ID}}">` with the cells `{{.Title}}`, `{{.Artists}}`, `{{.Genre}}`,
   `{{with .ReleaseYear}}{{.}}{{end}}`, `{{.Label}}`, `<td class="availability">{{.Available}}/{{.Total}}</td>`
   and, only `{{if .CanDelete}}`, `<td class="actions"><button type="button" class="danger"
   hx-delete="/web/albums/{{.ID}}" hx-target="closest tr" hx-swap="outerHTML"
   hx-confirm="Delete this album?">Delete</button></td>`. Rely on html/template's contextual
   autoescaping: never use `template.HTML`, never mark anything as safe.

5. `web/templates/login.html`: `{{define "title"}}Log in - Albums{{end}}` and `{{define "content"}}`
   with `<h1>Log in</h1>`, `{{if .Error}}<p class="error" role="alert">{{.Error}}</p>{{end}}` and
   `<form method="post" action="/login" class="login">` with a `<label>` and
   `<input type="email" name="email" required autocomplete="username">`, a `<label>` and
   `<input type="password" name="password" required autocomplete="current-password">`, and a submit
   button "Log in". Do NOT echo the submitted e-mail back into the form: a failed login must render a
   byte-identical page for an unknown e-mail and for a wrong password.

6. `web/static/app.css`: a small, readable stylesheet: system font stack, a max-width container, the
   topbar as a flex row with the user box on the right, zebra table rows, `.availability` right-aligned,
   `.empty td` muted and centred, `.danger` as a red outlined button, `.error` in red, `.inline` forms
   displayed inline, a subtle opacity on `tbody.htmx-request` while a request is in flight. No external
   fonts, no imports.

htmx itself is not generated: `web/static/htmx.min.js` is the official minified build of a pinned 2.x
release, downloaded verbatim; its version and sha256 are recorded in docs/web/htmx.sha256.

All files ASCII only. Output each file completely, no placeholders.

=== Prompt 3.1: go:embed for templates, static assets and migrations; single-binary wiring ===

htmx.min.js) exist. Today the binary reads nothing from disk except the migrations:
`repository.Migrate(dsn, dir)` in internal/repository/migrate.go builds its source with

=== Prompt 2.2: HTMX interactivity, web handlers and the cookie session (internal/handler/web, middleware) ===

Continue in the same repository. Available now: `web.Templates()` and `web.Static()` (fs.FS values carried
in `app.Config{JWTSecret, Templates, Static, CookieSecure}`); `internal/auth` with `ParseToken(secret, raw)
(Claims, error)`, `Claims{UserID int64; Role string}`, `IssueToken(secret, userID, role, ttl)`,
`TokenTTL = 24h`, `WithUser(ctx, Claims)`, `UserFromContext(ctx) (Claims, bool)`, `CheckPassword` and
`DummyHash`; `internal/middleware` with `Auth(secret)` (Authorization header only) and
`RequireRole(allowed ...string)` (401 `unauthenticated` without claims, 403 `forbidden` otherwise, JSON
envelope through `handler.WriteError`); `internal/handler` with `WriteJSON`, `WriteError`, the `Code*`
constants and the unexported helpers `pathID`, `readInput`, `writeRepoError`;
`repository.Repositories{Albums, Artists, Genres, Copies, Users}`; `AlbumRepository.List(ctx,
ListOptions{GenreID, Page, Limit})` preloading Artists and Genre; `CopyRepository.Availability(ctx, albumID)`;
`model.Album{ID, Title, Label, Genre{Name}, Artists []Artist{Name}, ReleaseYear *int}`;
`model.UserRoleMember`, `UserRoleStaff`, `UserRoleAdmin`. `AuthHandler.Login` in
internal/handler/auth_handler.go looks the account up by normalised e-mail, compares against
`auth.DummyHash` when the account is unknown or has an empty hash, and answers one generic 401. Same
conventions as before (full-sentence comments, ASCII only, three import groups, doc.go per package).

Generate:

1. Repository support.
   - `repository.ListOptions` gains `Query string`. In `gormAlbumRepository.List`, when Query is not blank,
     add `albums.title ILIKE ? ESCAPE '\' OR EXISTS (SELECT 1 FROM album_artists aa JOIN artists ar ON
     ar.id = aa.artist_id WHERE aa.album_id = albums.id AND ar.name ILIKE ? ESCAPE '\')` with the pattern
     `%` + query + `%` in which `\`, `%` and `_` of the query are escaped with `\`. Keep
     `Preload("Artists").Preload("Genre").Order("id")`, the genre filter and the pagination.
   - `CopyRepository` gains `AvailabilityForAlbums(ctx context.Context, albumIDs []int64)
     (map[int64]model.Availability, error)`: one query `SELECT album_id, count(*) AS total_copies,
     count(*) FILTER (WHERE status = 'available') AS available_copies FROM copies WHERE album_id IN ?
     GROUP BY album_id`; albums without copies are absent from the map; an empty id list returns an
     empty map without touching the database.
   - Update the fake repositories in internal/handler/fakes_test.go for the new method (a function field,
     nil fails the test with "unexpected AvailabilityForAlbums call", like the others).

2. `internal/handler/authenticate.go`: move the credential check of `AuthHandler.Login` into an exported
   `Authenticate(ctx context.Context, users repository.UserRepository, email, password string)
   (model.User, error)` that normalises the e-mail, loads the account, always runs exactly one bcrypt
   comparison (against `auth.DummyHash` for an unknown account or an empty hash) and returns the new
   exported sentinel `ErrInvalidCredentials` for every failure, or the repository error for anything
   that is not ErrNotFound. `Login` uses it; its responses do not change.

3. `internal/middleware/cookie.go`: `CookieAuth(secret, cookieName string) func(http.Handler) http.Handler`.
   It reads the named cookie; when it is present and `auth.ParseToken` accepts its value, next runs with
   the claims in the context (`auth.WithUser`); when the cookie is absent or invalid, next runs WITHOUT
   claims and nothing is written (the request is simply anonymous). It never reads the Authorization
   header: the web routes accept the cookie only and the API accepts the header only. `RequireRole`
   behind it produces the 401 and 403.

4. `internal/handler/web/` (package `web`, with a doc.go): the server-rendered UI.
   - `handler.go`: `Handler` holding the albums, copies and users repositories, the JWT secret, the cookie
     settings and the parsed templates; `New(repos repository.Repositories, templates fs.FS, secret string,
     cookieSecure bool) (*Handler, error)` parses the templates once; exported `const CookieName =
     "albums_token"`; `const pageLimit = 50` (the catalogue shows the first 50 matches ordered by id).
   - `templates.go`: parse `layout.html` + `partials/*.html` as the base set, then one clone per page
     (`catalog.html`, `login.html`) with `template.Must(template.Must(base.Clone()).ParseFS(fsys, name))`.
     `render(w, status, page, data)` executes the page's "layout.html" into a bytes.Buffer first and only
     then writes `Content-Type: text/html; charset=utf-8`, the status and the bytes; a template error is
     logged and answered with `handler.WriteError` and the existing internal-error code. `renderRows(w,
     data)` executes the "album_rows" template of the base set the same way.
   - `view.go`: `pageData{Title string; User *userView; CanDelete bool; Query string; Albums []albumRow;
     Error string}`, `userView{Email, Role string}`, `albumRow{ID int64; Title, Artists, Genre string;
     ReleaseYear *int; Label string; Available, Total int; CanDelete bool}`. View types stay in this
     package: internal/model/album.go must not get an `Artist string` field (CI greps for it).
     `rows(ctx, query, canDelete)` calls `Albums.List(ctx, ListOptions{Query: query, Page: 1,
     Limit: pageLimit})`, then `Copies.AvailabilityForAlbums` once for all the ids, and maps the result
     (artist names joined with ", ").
   - `catalog.go`: `Catalog` (GET /catalog) reads `q`, resolves the visitor from the context claims
     (CanDelete when the role is staff or admin; the user box needs the e-mail, so load the account with
     Users.Get when claims exist and render the visitor as anonymous on ErrNotFound) and renders the
     catalogue page. `Rows` (GET /web/albums) answers the "album_rows" fragment when the request carries
     `HX-Request: true`, otherwise redirects 303 to `/catalog?q=<query>`. `Delete` (DELETE
     /web/albums/{id}) parses the id (400 `invalid_id`; add a small exported `handler.PathID` wrapper
     around the existing helper so both packages share the parsing), calls `Albums.Delete` (ErrNotFound
     -> 404 `not_found`, other errors -> 500, the same mapping as the API) and answers `200 OK` with an
     empty body: htmx does not swap on a 204, while an empty 200 with `hx-swap="outerHTML"` removes
     the row.
   - `auth.go`: `LoginForm` (GET /login) renders the login page. `Login` (POST /login) parses the form
     (`r.ParseForm`, fields `email` and `password`), calls `handler.Authenticate`; on failure it renders
     the login page with status 401 and `Error: "invalid credentials"` (the same bytes for an unknown
     e-mail and a wrong password: the page never echoes the e-mail); on success it issues
     `auth.IssueToken(secret, user.ID, user.Role, auth.TokenTTL)`, sets the cookie `{Name: CookieName,
     Value: token, Path: "/", MaxAge: int(auth.TokenTTL.Seconds()), HttpOnly: true, SameSite:
     http.SameSiteLaxMode, Secure: cookieSecure}` and redirects 303 to `/catalog`. `Logout` (POST
     /logout) sets the same cookie with an empty value and `MaxAge: -1` and redirects 303 to `/catalog`.

5. `internal/app/app.go`: construct the web handler (`webhandler.New(repos, cfg.Templates, cfg.JWTSecret,
   cfg.CookieSecure)`, panic on error: a template that does not parse is a programming error) and
   register a commented "Web UI" group before the swagger route and the "/" fallback:
     cookie := middleware.CookieAuth(cfg.JWTSecret, webhandler.CookieName)
     webStaff := func(h http.HandlerFunc) http.Handler {
         return cookie(middleware.RequireRole(model.UserRoleStaff, model.UserRoleAdmin)(h))
     }
     GET /catalog              cookie(http.HandlerFunc(ui.Catalog))
     GET /login                ui.LoginForm
     POST /login               ui.Login
     POST /logout              ui.Logout
     GET /web/albums           cookie(http.HandlerFunc(ui.Rows))
     DELETE /web/albums/{id}   webStaff(ui.Delete)
     GET /static/              http.StripPrefix("/static/", noDirListing(http.FileServer(http.FS(cfg.Static))))
   where `noDirListing` answers 404 for any path that ends in "/". Wrap every web route (not the API)
   in `http.NewCrossOriginProtection().Handler(...)` from Go 1.25 so a cross-site DELETE is refused even
   with a valid cookie. Keep the API groups exactly as they are, including the literal text
   `protected(middleware.RequireRole` that CI greps for, and keep `"/"` as the JSON 404 for every
   method: a root page would break the pinned test.

Do not add tests (they are written separately: internal/app/web_test.go exists and is red, and
internal/handler/web/catalog_test.go comes from prompt 3.2). Output each new or changed file completely.
